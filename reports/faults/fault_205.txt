(inside the `if (isOneOf(ch, terminators))` branch)

Patch (single-line):
    pos++;          ->          ;

Why this is the fault.
The Javadoc for parseToken says it returns "the parsed token", i.e.
the prefix up to but not including the first terminator. The buggy
version does `pos++` *before* `break`, so the returned substring
includes the terminator. Failing tests I traced:

  parseToken("2 M", {'#','4','4',' ','4','4'})  expected "2"  got "2 "
  parseToken("0100-01-01###...", {'4','a',' ','4','#'})
                                expected "0100-01-01"  got "0100-01-01#"
  parseToken("=U[dDkbutQZ<K", terminators with 'Q')
                                expected "=U[dDkbut"   got "=U[dDkbutQ"

Removing the `pos++` on line 205 fixes all of them. Line 208's
`pos++` (the one used when no terminator is found) is left alone, so
strings without a terminator still return the whole string.
